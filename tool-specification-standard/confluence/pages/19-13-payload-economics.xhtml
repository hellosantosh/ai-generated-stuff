Context is the scarcest resource in an agent system and the one most casually spent. A tool that returns everything it knows is not being helpful; it is charging every future turn of the conversation for data nobody asked for.

13.1 The standing tax

Descriptors are re-sent on every turn. The arithmetic is worth doing once, in front of the people who will be surprised by the invoice:

QuantityModest catalogSprawling catalog
Tools offered2060

The difference is not a rounding error on a cloud bill, and the sprawling catalog also selects worse. Both problems have the same fix.

Every tool MUST enforce a result size ceiling in code and MUST truncate with disclosure (TS-OUT-07) rather than returning an unbounded payload. "The customer has 340 positions" is not an excuse; it is the case the ceiling exists for.

13.3 What to cut from a payload

CutReasoning
Null and absent fieldsOmit rather than emitting "field": null — unless null is itself meaningful, which the output schema should then say.
Internal identifiers with no caller useSurrogate keys, partition hints, ETL timestamps. They cost tokens and leak topology.
Hypermedia linksA model cannot be trusted to follow a URL, and should not be given one it might quote to a customer. Express capability as the presence of a tool.
Redundant derivationsEmit marketValue and unrealizedPnl; drop unrealizedPnlPercent if the model can compute it — but keep any derivation whose convention it could get wrong.
Repeated constant contextDo not repeat accountId, currency, and asOf on all 340 rows. Put them once at the envelope level.
Pre-formatted display stringsOne authoritative numeric form in structuredContent, one prose rendering in content. A third, half-formatted copy helps nobody.

13.3.1 Verbosity levels

Rather than a caller-supplied field list — which models compose badly and which makes the output schema unstable — offer three named levels:

13.4 A worked reduction

Upstream record, passed through — 41 lines per position

json

340 positions × ~600 tokens ≈ 204,000 tokens. Exceeds most context windows outright, and tells the model the name of a production host.

Shaped for the question — 9 lines per position

text

25 positions × ~70 tokens ≈ 1,750 tokens, plus an explicit truncation notice and a suggestion to filter. Two orders of magnitude, and a better answer.

13.5 Representing numbers

RuleLevelRequirement
TS-OUT-13RedMUST Monetary amounts and quantities MUST be decimal strings — "62137.50" — never IEEE-754 numbers. Binary floating point cannot represent a cent, and the error is silent, compounding, and eventually a reconciliation break.
TS-OUT-14RedMUST Every monetary value MUST be accompanied by an ISO 4217 currency, at the value or at the envelope level. Never assume USD.
TS-OUT-15RedMUST Structured values MUST NOT carry locale formatting — no thousands separators, no currency symbols, no parenthesized negatives. Formatting belongs in the text rendering, where (2,110.00) is spelled -2,110.00 USD because parentheses for negatives are a convention a model will misread.
TS-OUT-16RedMUST Timestamps MUST be RFC 3339 with an explicit UTC offset. Dates that are genuinely dates — settlement date, expiry — are YYYY-MM-DD, and the description MUST name the time zone they are interpreted in.
