The catalog answers the questions a retail brokerage customer actually asks an assistant. It is deliberately small: six tools, no resource mirroring, and every piece of domain knowledge that could produce a wrong answer pushed into the tool rather than left for the model to reconstruct.

What is deliberately absent

There is no brokerage_account_get: the list tool returns everything a single-account read would, and two tools that differ only in cardinality are two opportunities to pick the wrong one. There is no brokerage_instrument_get: instrument details arrive inside the results that need them. There is no brokerage_orders_manage — see §25.1 — and no tool that mirrors the REST surface's transaction history, because the questions it answers were not in the top twenty (§12.2). Each of these is a decision, revisited when the utterance data says so.

18.2 Shared types

Five shapes recur across every tool. They are defined once in Appendix B and referenced by every descriptor, so that quantity means the same thing everywhere (TS-INP-04).

Decimal — the money and quantity type

json

A string, always. 0.1 + 0.2 is not 0.3 in IEEE-754, the error compounds across a portfolio, and the resulting reconciliation break is discovered by an operations team rather than a test. The currency travels with it, at the value or at the envelope level (TS-OUT-14).

The completeness block

asOf and basis

Every result states the instant it was true and the convention it was computed under. The basis vocabulary differs by tool because the honest answers differ: REALTIME / DELAYED_15M / PRIOR_CLOSE for prices; INTRADAY_ESTIMATE / TRADE_DATE / SETTLED for money.
