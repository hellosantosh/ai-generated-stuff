The input schema does two jobs at once. It is the validation contract the gateway enforces, and it is the instruction manual the model reads while composing arguments. A schema tight enough for the first job usually solves the second for free — which is the central insight of this section.

7.1 The schema profile

TS-INP-01 — MUST#A32A2Asolid2#F4F5F7#FFFFFF

inputSchema MUST be a JSON Schema 2020-12 document whose root is {"type": "object"} with an explicit properties map, an explicit required array (possibly empty), and "additionalProperties": false.

A tool that takes no arguments still declares {"type":"object","properties":{}, "required":[],"additionalProperties":false}. Omitting the schema entirely is not the same statement and several runtimes treat it as "arguments unconstrained".

7.1.1 Permitted keywords

KeywordUse
type, properties, required The backbone. type may be an array to express nullability: "type": ["string", "null"].
descriptionRequired on every property (§7.5).
enum, constThe most valuable keywords in the profile (§7.3).
defaultPermitted, but the behavior on omission MUST also be stated in prose (§7.4).
examplesOne or two realistic values. Worth more than a sentence of description.
minimum, maximum, exclusiveMinimum, exclusiveMaximum, multipleOf Numeric bounds. Always bound a number that reaches a system of record.
minLength, maxLength, pattern String bounds. Every free-text field carries a maxLength.
format Restricted to date, date-time, duration, uuid, and uri. Others are not consistently validated and give false assurance.
items, minItems, maxItems, uniqueItems Arrays. maxItems is mandatory (TS-INP-08).
$ref, $defs Reuse from the shared type library (Appendix B). Local or pinned-immutable only.
oneOf Permitted only as a discriminated union with a const tag, at most three branches (§7.3.2).

7.1.2 Prohibited keywords

KeywordWhy
if / then / else, dependentSchemas, dependentRequired Conditional structure is where model accuracy falls off a cliff: the model reads the properties and largely ignores the conditional envelope, producing arguments that are individually plausible and jointly invalid. Split into two tools, or enforce the rule in the implementation and explain it in prose.
not, anyOf, allOf Negation and unconstrained unions are close to unreadable as instructions. allOf additionally interacts badly with additionalProperties: false in several validators.
patternProperties, propertyNames, additionalProperties: true Open maps are unvalidatable, unreviewable, and an injection surface. If the keys are unknown at design time, the design is not finished.
$dynamicRef, $dynamicAnchor, recursive $ref Unbounded structures cannot be size-limited, and recursion is not something to put in front of a generative caller.
nullable Not a JSON Schema keyword at all. Left in a document it is silently ignored, so a field you believe is nullable validates as non-nullable. Use "type": ["string","null"].
Remote $ref resolved at invocation time Turns a validation into a network call, an availability dependency, and a tampering surface (TS-GEN-07).
TS-INP-02 — SHOULD#8A5A00solid2#F4F5F7#FFFFFF

An input schema SHOULD declare no more than 12 top-level properties and SHOULD NOT nest more than two levels deep. Beyond that, argument-composition accuracy degrades sharply and the tool is usually doing two jobs.

7.2 Parameter naming and shape

RuleLevelRequirement
TS-INP-03RedMUST Property names MUST be lowerCamelCase and MUST use the domain's own vocabulary — accountId, timeInForce, limitPrice — not invented synonyms.
TS-INP-04RedMUST A property name MUST mean the same thing in every tool in the catalog. quantity cannot be shares in one tool and contracts in another. Where a concept recurs, take it from the shared type library (Appendix B) rather than redefining it.
TS-INP-05YellowSHOULD Boolean parameters SHOULD be named positively and default to the conservative value: includeClosed defaulting to false, never excludeClosed defaulting to false. Double negatives are reliably mis-set.
TS-INP-06YellowSHOULD Inputs SHOULD be flat. Nesting that exists only to mirror an upstream request body is noise; flatten it and let the implementation rebuild the shape.
TS-INP-07RedMUST Identifiers MUST be opaque, prefixed, and pattern-constrained (acct_, ord_, inst_). The prefix tells the model which identifier goes in which slot, and the pattern stops a well-formed-looking hallucination before it reaches a system of record.
TS-INP-08RedMUST Every array parameter MUST declare maxItems, and every string parameter MUST declare maxLength.

7.3.1 Enumerations

TS-INP-09 — MUST#A32A2Asolid2#F4F5F7#FFFFFF

Any parameter whose valid values are a known finite set MUST be an enum. Enumerated values MUST be SCREAMING_SNAKE_CASE and MUST match the domain enumerations in Appendix D exactly — the same tokens the systems of record and the customer statement use.

Where an enumeration is long (a currency list, an exchange list) or grows frequently, use a pattern plus a prose pointer to the tool that enumerates valid values, rather than a 180-member enum that costs tokens on every turn. Where an enumeration is short and consequential — order status, side, time in force, account type — spell it out.

7.3.2 Unions, and the alternative

When two shapes are genuinely different, the default answer is two tools, not one tool with a union. Two tools give you two accurate descriptions, two accurate annotation sets, two risk tiers, and two audit identities. That is almost always worth more than the saved descriptor.

7.4 Required, optional, and default

RuleLevelRequirement
TS-INP-10RedMUST A parameter is required only if the tool genuinely cannot proceed without it. Marking a parameter required to force the model to "think about it" causes the model to invent a value instead.
TS-INP-11RedMUST Every optional parameter's omission behavior MUST be stated in its description in prose, not only in default. Models read prose far more reliably than they read schema annotations.
TS-INP-12RedMUST Defaults MUST be the narrow, conservative, least-surprising choice: the smallest page, the current account only, the shortest date window, exclusions on. A default that widens scope is a defect even when it is convenient.
TS-INP-13GreyNEVER A parameter that changes the tool's safety characteristics — whether a change is simulated or real, whether validation is skipped, whether a confirmation is required — MUST NOT exist. Those are separate tools with separate annotations (§9.1, §25.2).

7.6 Standard parameter patterns

These names are reserved firm-wide. Where a tool needs the concept, it MUST use the name and shape below rather than inventing an equivalent (TS-INP-15).

ParameterShapeSemantics
pageSizeinteger, 1–100, default 25 Maximum items to return. Never call it limit, count, or top.
cursorstring, maxLength 512 Opaque continuation token from a previous result's nextCursor. Offset and page-number pagination are prohibited — they produce duplicates and gaps against a moving book, which is exactly what a positions or orders collection is.
asOfstring, date-time Point-in-time read. Omitted means now. A tool that cannot honor a historical asOf must not accept the parameter at all.
fromDate, toDatestring, date Inclusive date window in the account's reporting time zone. Declare the maximum span in the description and enforce it.
detailenum SUMMARY | STANDARD | FULL Verbosity of the result. Preferred over a caller-supplied field list, which the model composes badly (§13.3).
idempotencyKeystring, uuid Required on every non-idempotent state-changing tool. The implementation deduplicates for at least 24 hours and returns the original result on replay (§14.4).
confirmationTokenstring, maxLength 512 Short-lived token issued by the matching preview tool, binding an execution to a previewed outcome (§14.2).
reasonstring, maxLength 280 Why the action is being taken, captured verbatim into the audit record. Required on risk tier 3 tools.
TS-INP-16 — MUST#A32A2Asolid2#F4F5F7#FFFFFF

A tool MUST NOT accept a parameter it cannot honor. Offering an asOf on a tool with no history, or a currency on a tool that only reports in the account's base currency, is worse than omitting it: the model will supply the parameter and silently receive an answer that does not match what it asked for.

7.7 Prohibited input patterns

TS-INP-17 — MUST#A32A2Asolid2#F4F5F7#FFFFFF

An input schema MUST NOT contain any of the patterns below. Each is rejected at review and by the linter; the right-hand column is the reason, not a mitigation.
PatternWhy it is prohibited
Identity parameters
userId, customerId, onBehalfOf, role, tenantId		 Identity comes from the identity plane, never from the model. A tool that accepts an identity argument is a tool that can be talked into acting as someone else, and it will be. Hard rejection at review (TS-SEC-02).
Credentials
apiKey, token, password		 Secrets must never enter a context window. They would be logged, cached, and possibly returned to the user (TS-SEC-03).
Pass-through query languages
sql, filterExpression, graphqlQuery, jsonPath		 Unvalidatable, unauditable, and an injection surface with the model as the injector. If the query space is genuinely open, the tool is a database connection wearing a costume; expose the three questions actually being asked instead.
Operation discriminators
action, operation, mode, command		 Collapses several risk profiles into one descriptor, making annotations, risk tiers, approval policy, and the audit record all wrong simultaneously (§5.3, §25.1).
Safety-defeating flags
force, skipValidation, dryRun, override		 A flag that changes whether a tool is dangerous means the annotations describe one of two tools. Split them (TS-INP-13).
Caller-supplied URLs or paths A tool that fetches a URL supplied by the model is a server-side request forgery primitive. Permitted only against an allow-list held in configuration, never in the argument.
Unbounded arrays and blobs A cost, latency, and denial-of-service vector. maxItems and maxLength are mandatory (TS-INP-08).
Environment or routing hints
env, region, useCache, debug		 Deployment concerns the model must not be able to reason about or influence.
