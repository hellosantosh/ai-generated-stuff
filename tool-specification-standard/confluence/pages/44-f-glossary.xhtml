TermMeaning in this standard
AgentA system that uses a model to decide which tools to invoke and in what order, on behalf of a principal.
AnnotationOne of four boolean behavioral hints in the descriptor. Advisory to a runtime; never a security control (§9.2).
AudienceA set of principals to whom a scoped view of the catalog is served.
BasisThe convention under which a figure was computed — settled versus trade-date cash, real-time versus delayed price.
CatalogThe system of record for descriptors: versions, hashes, owners, tiers, audiences, lifecycle.
Composite toolA tool that joins several sources or applies domain rules server-side, so the caller does not have to (§12.3).
Confirmation tokenA single-use, short-lived capability issued by a preview tool and required by its execute counterpart (§14.2).
DescriptorThe eight-field document that defines a tool (§4).
Execution errorA failure the tool returns inside a successful transport response, with isError: true (§11.1).
GatewayThe enforcement point between agent and implementation: identity, validation, policy, approval, quota, audit (§3.1).
PrincipalThe human or legal person on whose behalf a tool is invoked, and whose authority is used.
Result envelopecontent plus structuredContent plus isError (§8.1).
Risk tierThe firm's classification, 0 to 3, that drives approval, evidence, and monitoring (§9.3).
Selection accuracyHow often the right tool is chosen for a real user question (§27.3).
Silent wrongnessAn invocation that succeeded, returned valid data, and produced a wrong answer. Measurable only by reading conversations (§16.2).
TerminalA lifecycle state that can never change again. Expressed as a boolean, never inferred from a status string (§22.1).
ToolA capability of the firm, described precisely enough that a model can decide to use it, use it correctly, and be held to account for having used it.
