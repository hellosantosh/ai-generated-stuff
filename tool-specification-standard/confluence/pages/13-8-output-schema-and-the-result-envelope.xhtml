What a tool returns is read twice: once by a model that will paraphrase it to a customer, and once by a human reconstructing what happened. The envelope in this section serves both without making either read the other's format.

8.1 The envelope

Every invocation returns the same three-field envelope, success or failure:

json
FieldRules
content An ordered array of presentation blocks. MUST contain at least one text block. Additional block types — image, audio, resourceLink, resource — MAY follow (§8.5).
structuredContent A JSON object that MUST validate against the descriptor's outputSchema. This is the authoritative result; anything a downstream system computes from, it computes from here.
isError Boolean. true means the tool ran and could not do its job (§11.1). Transport and protocol failures are not signaled here — they never reach the tool.
TS-OUT-01 — MUST#A32A2Asolid2#F4F5F7#FFFFFF

Every tool MUST declare an outputSchema and MUST return both content and structuredContent on every invocation, including error invocations. Runtimes differ in which one they surface to the model; a tool that populates only one is broken on half the estate and nobody notices until a migration.

8.2 The dual-rendering rule

The text block is not a second-class debug string. It is what several runtimes actually put in front of the model, what an approval dialog shows, and what an auditor reads. It is also the only part of the result that will survive being pasted into an incident ticket.

RuleLevelRequirement
TS-OUT-02RedMUST The text rendering MUST be derived from structuredContent by the implementation — generated, not hand-maintained — so the two cannot disagree.
TS-OUT-03RedMUST The text rendering MUST NOT contain any fact absent from structuredContent, and MUST carry the facts a reader could be materially misled by omitting: the as-of time, the currency, the sign of a position, and any truncation.
TS-OUT-04YellowSHOULD The text rendering SHOULD be compact — a few hundred characters for a typical result — and SHOULD NOT be a pretty-printed dump of the structured payload. Duplicating the whole payload as text doubles the token cost of every call for no gain.
TS-OUT-05RedMUST Monetary and quantity values in the text rendering MUST carry their currency and their sign explicitly. "−98,240.00 USD" and "SHORT 400" are unambiguous; "98240" is a defect waiting for a customer complaint.

8.3 Provenance, as-of, and completeness

Three pieces of metadata turn a payload into something a regulated firm can stand behind. All three live inside structuredContent, because they are data about the answer, not decoration.

MemberRequirement
asOf
RFC 3339, UTC, always		 RedMUST be present on every result carrying data that can change. It is the instant the data was true, not the instant the response was built. Without it, a model will present a 20-minute-old mark as the current price, in a market that moved.
basis
how the number was derived		 RedMUST be present on any computed or convention-dependent figure. A balance is SETTLED, TRADE_DATE, or INTRADAY_ESTIMATE; a price is REALTIME, DELAYED_15M, or PRIOR_CLOSE. The same question has several correct answers and the reader must know which one they received.
completeness
what you did not get		 RedMUST be present on every collection result: {returned, totalMatching, truncated, nextCursor}. totalMatching may be null where it is genuinely unknowable, but truncated never may.
disclosures
what must be said		 YellowSHOULD carry compliance text the firm requires to accompany the figure — delayed-quote notices, estimate caveats, tax-lot method. Carrying them in the payload puts them where the agent can surface them, rather than in a description where they cost tokens on every turn and are reproduced unreliably.
The single most damaging omission in a financial tool

A number without an asOf and a basis is not a fact, it is a rumour with a decimal point. "You have $84,360 of buying power" is true of settled cash, of margin buying power, of day-trading buying power, or of an intraday estimate that will be restated at the close — and those four numbers can differ by a factor of four in the same account at the same instant. The tool knows which one it computed. Say so.

8.4 Pagination and truncation

A model is a poor paginator. It will follow a cursor once, sometimes twice, and then summarize what it has as though it were everything. Design for that rather than against it.

RuleLevelRequirement
TS-OUT-06RedMUST Collections MUST use opaque forward cursors. Offset and page-number pagination MUST NOT be used against a mutable collection.
TS-OUT-07RedMUST When a result is truncated, completeness.truncated MUST be true and the text rendering MUST say so in words: "showing 25 of 340 positions". Silent truncation causes the model to state a partial total as a complete one.
TS-OUT-08YellowSHOULD A truncated result SHOULD tell the reader how to narrow rather than how to continue: "filter by assetClass or symbol to see fewer than 340". Narrowing produces a correct answer in one more call; paging produces fourteen calls and an abandoned loop.
TS-OUT-09YellowSHOULD Where a caller is likely to want the whole collection only in order to compute an aggregate, the catalog SHOULD offer a summarize tool that computes it server-side. Totals computed by a model over a paginated collection are wrong often enough to matter.

8.5 References instead of payloads

Not everything belongs in a context window. A confirmation PDF, a tax-lot export, a year's transactions, an image of a chart: these are returned by reference, as a resourceLink block naming a URI, a media type, a size, and an expiry.

json TS-OUT-10 — MUST#A32A2Asolid2#F4F5F7#FFFFFF

Binary content and any text payload over 100 KB MUST be returned by reference rather than inline. Reference URIs MUST be short-lived and MUST require the principal's own authority to dereference — a link that anyone holding the URI can fetch has moved customer data outside the entitlement model.

8.6 Empty, partial, and stale results

SituationRequired behavior
Empty isError: false, an empty array, and a text rendering that says what the emptiness means: "This account holds no positions." Never an error, and never a bare [] — a model shown an empty array with no prose reports an outage about half the time.
Not found An error with code NOT_FOUND for a single-entity get; an empty collection for a list. The distinction matters: "that order does not exist" and "you have no orders" are different customer answers.
Partial
one source degraded		 Permitted only where the missing part is separable and disclosed: return what is available, set completeness.truncated or a degraded flag, name what is missing, and say it in the text. A result that silently omits one custodian's positions is worse than no result.
Partial, where the number will be relied on RedMUST fail instead. A buying-power figure computed from a margin engine that did not respond is not a degraded answer, it is a wrong one. Balances, buying power, and anything that gates a trading decision MUST NOT be returned partially computed (TS-OUT-11).
Stale Return it with an honest asOf and basis, plus a stale: true flag where the data is older than the tool's own freshness target. Let the reader decide; do not decide for them by hiding it.
