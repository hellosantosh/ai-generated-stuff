9Behavioural annotations and risk tiers

Annotations let a runtime that has never seen your tool reason about it: whether to offer it to an autonomous agent, whether to demand a confirmation, whether a retry after a timeout is safe. They are the machine-readable half of "what does this thing do to the world".

9.1The four behavioural hints

AnnotationDefaultMeaning, and what a runtime does with it
readOnlyHintfalse True means the tool changes nothing in any system, including caches, counters, and audit-visible state. Runtimes use it to decide what an agent may do without supervision, what may run speculatively or in parallel, and what is safe to replay while debugging. If the tool writes anything at all — even a search-history row — this is false.
destructiveHinttrue Meaningful only when readOnlyHint is false. True means the change may be irreversible or may overwrite existing state; false means it is purely additive. Placing an order is destructive: it can fill in milliseconds and cannot be un-filled. Adding a symbol to a watchlist is additive.
idempotentHintfalse Meaningful only when readOnlyHint is false. True means repeating the identical call has no additional effect. This is the annotation that tells a runtime whether a timeout can be retried. Cancelling an already-cancelled order is idempotent; placing an order is not, unless an idempotencyKey makes it so — and if it does, say so here and require the key.
openWorldHinttrue True means the tool reaches outside the firm's controlled domain — the public internet, a market data vendor, a counterparty. False means a closed, enumerable universe. Runtimes use it to decide what may be quoted to a customer without attribution and what content needs treating as untrusted.

TS-ANN-01 MUST All four annotations MUST be stated explicitly, even where the value equals the default. The defaults are deliberately pessimistic so that an omission fails safe; but an omission also means the reviewer cannot tell whether the author decided or forgot.

TS-ANN-02 MUST Annotations MUST be consistent with the operation verb in the tool's name (§5.3). A tool named ..._list with readOnlyHint: false fails the linter, and a tool named ..._place with readOnlyHint: true fails it harder.

9.2Hints are advisory, never enforcement

Read this paragraph twice before designing a control around an annotation

An annotation is an assertion made by whoever wrote the descriptor. For a tool the firm builds and signs, that assertion is as trustworthy as the review that approved it. For a tool supplied by a third party, it is a claim by an untrusted party about their own software — and a readOnlyHint: true on someone else's tool is worth precisely what any self-certification is worth. No security control may depend solely on an annotation.

The firm's controls therefore derive from the risk tier in the governance block, which is set by the tool's owner, verified at review, recorded in the catalogue, and signed — not from the annotations, which are conveniences for the runtime and hints for the agent. Annotations and risk tier must agree; where they disagree, the linter fails the build and a human decides which one was wrong.

9.3The risk tier

TierScopeBrokerage examplesBaseline controls
T0
Reference		 Reads data that is public or firm-wide reference. No customer, no position, no money. Market calendar · symbol lookup · contract specifications · fee schedule Audit event. No entitlement beyond authentication. Freely available to autonomous agents.
T1
Customer read		 Reads customer-identifying or position data. Changes nothing. Accounts · positions · balances · order status · transaction history Entitlement check at three points (§10.4). Full argument-and-result audit. Per-principal rate limit. Level 2 conformance. No confirmation needed.
T2
Reversible change		 Changes state, but the change is reversible and not financially material. Set an account nickname · create a price alert · request a statement · save a watchlist T1 controls, plus: idempotency key, explicit notification to the principal, and a documented reversal path.
T3
Material		 Moves money, creates market exposure, or makes an irreversible change to a customer's holdings or standing instructions. Place, replace, or cancel an order · transfer funds · change beneficiaries · exercise an option T2 controls, plus: mandatory human confirmation bound to the exact arguments, two-step preview-then-execute, reason captured, dedicated kill switch, heightened monitoring, and Level 2 conformance with an independent security review.

TS-ANN-03 MUST Every descriptor MUST declare a riskTier. A tool whose tier is disputed at review defaults to the higher tier until the dispute is resolved in writing.

Cancellation is tier 3, and people argue about it

Cancelling an order feels like undoing something and therefore harmless. It is not: a cancelled order does not fill, and an order that does not fill in a moving market is a realised economic difference for the customer. It is also irreversible — you cannot un-cancel; you can only place a new order at a new price. Treat cancellation exactly as you treat placement.

TS-ANN-04MUST Tier 3 tools MUST supply a confirmationTemplate that renders, in the principal's language: the action, the identified account in customer-facing terms, the instrument in words, the quantity and the money, the reversibility, and the material consequence.

10Governance metadata

Everything an architecture board, a risk function, an auditor, or an on-call engineer needs to know about a tool — and nothing the model needs. It lives in _meta precisely so that it never competes for context.

10.1The governance block

MemberRequiredContent
versionMUST Semantic version of the tool contract. Bumped by the rules in §17.2.
lifecycleMUST draft | active | deprecated | retired. The catalogue will not serve a draft or retired tool to a production audience.
conformanceLevelMUST L0–L3 per §1.3. Asserted by the owner, verified by the certification gate (§27).
riskTierMUST 0–3 per §9.3.
ownerMUST {team, contact, escalation}. A distribution list is not an owner; a team with an on-call rotation is.
dataClassificationMUST The highest classification of anything the tool can return, per the firm's data classification standard (§10.3).
containsPii, piiFieldsMUST Whether results can contain personal data, and which output fields carry it — expressed as JSON Pointers into the output schema, so redaction and retention can be applied mechanically.
entitlementsMUST The scopes a principal must hold (§10.4). An empty array is a positive assertion that none are needed and is scrutinised at review.
approvalMUST {mode, confirmationTemplate, expiresInSeconds} per §9.4.
recordKeepingMUST {auditEvent, retention, regulatoryBasis} — the audit event name, an ISO 8601 retention duration, and the obligations that drive it.
costSHOULD {class, p95LatencyMs, unitCost}. Lets an orchestrator prefer a cheap tool and a capacity planner forecast.
rateLimitMUST Per-principal and per-tenant ceilings. An agent in a retry loop is the most common source of load a tool will ever see.

deprecationWhen deprecated {since, sunset, successor, migrationNote} (§17.4).

10.2Ownership and lifecycle

TS-GOV-01 MUST Every tool MUST name an owning team with a paging escalation path. The catalogue MUST re-verify ownership quarterly and automatically move a tool whose owner cannot be confirmed to deprecated, then retired ninety days later.

This rule exists because of a failure mode specific to tool catalogues: tools are cheap to add and invisible once added. A REST endpoint with no owner eventually breaks and someone notices. A tool with no owner keeps working, keeps returning customer data to agents, and keeps being selected — silently, correctly, and unaccountably — for years.

10.3Data classification

ClassificationIn this domainConsequence
publicMarket calendar, contract specsNo restriction.
internalAggregate firm statisticsEmployee agents only.
customer-confidentialAccounts, positions, balances, orders Entitlement-gated; encrypted in transit and at rest; results excluded from model training and from any vendor retention; egress assessed before any L3 exposure.
restrictedGovernment identifiers, full account numbers, compliance case data Must not be returned by a tool at all in the ordinary case. Where an identifier is genuinely needed it is masked to the last four characters and the unmasked form requires a separate, tier-3, dual-control tool.

TS-GOV-02 MUST A tool MUST return the minimum data that answers its question. Returning an entire upstream record because it was convenient is a data-minimisation failure, and in an agent context the data does not merely sit in a response object — it enters a context window, is retained in conversation history, and may be forwarded to a model provider.

10.4Entitlements

Entitlement scopes are named <domain>:<resource>:<action> and reused across the firm's API and tool estates, so that a customer's consent means the same thing whichever surface consumes it.

ScopeGrants
brokerage:accounts:readEnumerate accounts and read their attributes, with masked account numbers.
brokerage:positions:readRead holdings, cost basis, and unrealised profit and loss.
brokerage:balances:readRead cash, buying power, and margin detail.
brokerage:orders:readRead order status, history, and executions.
brokerage:orders:writePlace, replace, and cancel orders.

TS-GOV-03 MUST Entitlements MUST be enforced at three points: (a) catalogue visibility — an agent is not offered a tool its principal cannot use; (b) the gateway, before invocation; (c) the implementation, against the specific resource named in the arguments. Point (c) is the one that stops a customer reading another customer's account, and it is the one most often skipped because (a) and (b) feel sufficient.

Visibility is an entitlement decision, not a convenience

Offering an agent a tool that its principal may not invoke wastes context, invites a failed call, and — worse — tells the model that the capability exists, which is enough for it to describe the capability to the customer. "I can see there's a way to place orders but I'm not permitted" is a disclosure the firm did not intend to make.
