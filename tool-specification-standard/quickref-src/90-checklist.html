14Review checklist

The working document for a review meeting. Items in bold are gating: a failure means the tool does not ship. Full version with commentary is Appendix E of the standard.

Identity & description

  • TS-NAM-01 Name matches the grammar; domain segment present; final segment in the vocabulary
  • TS-NAM-02 Globally unique; never used before
  • TS-NAM-07 Title ≤60 chars, human-readable, names the consequence at tier 3
  • TS-DSC-01 Purpose, "use when", "do not use", result orientation, effects
  • TS-DSC-05 Nearest neighbors named by exact wire name
  • TS-DSC-02 ≤2,000 characters
  • TS-DSC-06 No instructions about agent behavior outside this tool
  • TS-DSC-07 Static, reviewed, not templated at runtime
  • §18.3 Every domain convention that could produce a wrong answer is stated

Schemas

  • TS-INP-01 Closed object; explicit required; additionalProperties: false
  • TS-INP-09 Every finite-valued parameter is an enum from Appendix D
  • TS-INP-07 Identifiers prefixed and pattern-constrained
  • TS-INP-08 maxItems on arrays, maxLength on free text
  • TS-INP-14 Every parameter description says more than its type
  • TS-INP-12 Defaults are the conservative choice
  • TS-INP-17 No identity, credential, query language, discriminator, or safety flag
  • TS-INP-16 No parameter the tool cannot honor
  • TS-OUT-01 Output schema declared; both content and structuredContent on every path
  • TS-OUT-03 asOf and basis on every figure that can change
  • TS-OUT-07 completeness present; truncation stated in the text
  • TS-OUT-13 Money and quantities are decimal strings with a currency
  • §8.6 Empty is success; partial is disclosed or refused

Errors

  • TS-ERR-01 Domain failures are execution errors, not transport errors
  • TS-ERR-02 Imperative remediation naming the next action
  • TS-ERR-03 Constraint violations state the permissible bound
  • TS-ERR-06 Every upstream failure mapped and tested; default branch alerts
  • §11.5 No stack traces, hostnames, upstream prose, or unmasked identifiers
  • §11.3 INVALID_ARGUMENT and BUSINESS_RULE_VIOLATION not conflated

Classification & control

  • TS-ANN-01 All four annotations, consistent with the operation verb
  • TS-ANN-03 Risk tier declared and defensible; state-changing ⇒ tier 2+
  • TS-ANN-04 Tier 3 has a confirmation template a human can act on
  • TS-ANN-05 Approval bound to an argument hash, and expires
  • TS-SEC-07 Non-idempotent tools require a key; dedupe 24 h
  • TS-SEC-02 No identity accepted from the caller
  • TS-SEC-08 Resource-level authorization shown by a negative test
  • TS-SEC-10 No token passed through downstream
  • TS-SEC-11 Externally-sourced free text neutralized and labeled
  • TS-SEC-12 Kill switch for tier 2+, tested

Governance & evidence

  • TS-GOV-01 Named owning team with a paging escalation path
  • TS-GOV-02 Minimum necessary data; classification and PII mapped
  • TS-GOV-03 Entitlements at catalog, gateway, and implementation
  • TS-GOV-04 Per-principal rate limit declared
  • TS-OBS-01 Audit record on every path, including the descriptor hash
  • TS-VER-04 Evaluation suite exists and has run against this version
  • §27.3 Selection, refusal, argument, interpretation thresholds met
  • TS-SEC-09 Descriptor hash registered with the catalog
  • TS-CAT-05 Exceptions recorded with a compensating control and an expiry

Catalog fit

  • TS-CAT-01 Answers one question a user actually asks
  • TS-CAT-02 The agent's catalog stays within 25 tools
  • §12.5 One sentence distinguishes it from its nearest neighbor — in both descriptions
  • §12.3 No common question needs ≥3 calls plus a convention the model must know

Six questions to ask out loud

  1. "Read me the description." Unreadable aloud, or ninety seconds long, or no sentence starting "Do not use" — not ready.
  2. "What is the nearest tool, and what sentence tells them apart?" A pause is a confusability problem.
  3. "What does the customer see if this is wrong?" A specific wrong sentence, not "an error".
  4. "Show me the negative test" where the customer asks for someone else's account. Not the code — the test.
  5. "Who is paged at 2am, and what do they turn off?"
  6. "What did the evaluation say about the cases where it should refuse?" Selection accuracy is easy to score well on. Refusal accuracy is where the risk lives.
