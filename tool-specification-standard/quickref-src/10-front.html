Conformance levels

LevelNameRequiresPermitted exposure
L0Registered Parses against the descriptor schema.Dev and test only.
L1Conformant Every MUST satisfied; linter clean; named owner; structured errors; audit events. Internal agents, non-customer data, tier 0–1.
L2Certified L1 + security review + evaluation evidence + entitlement sign-off + SLO + kill switch + retention. Mandatory for customer data, money, or positions.
L3Externally exposed L2 + egress assessment + contractual controls + tenant isolation proof + annual red team. Agents the firm does not operate.

Reading a rule

MUST Gating. Fails the build and the review.
SHOULD Departure needs a recorded reason.
MAYPermitted, no expectation.
NEVER MUST NOT, with no exception path.

1The descriptor

Eight top-level fields. No others — extensions go inside _meta under a namespaced key (TS-GEN-02). 

{
  "name":        "brokerage_positions_list",       // MUST  ^[a-z][a-z0-9_]{2,63}$ · permanent · §5
  "title":       "List the holdings in an account", // MUST  ≤60 chars · for humans approving/auditing · §5.4
  "description": "Returns the current open holdings …", // MUST  7 parts · ≤2,000 chars · §6

  "inputSchema": {                             // MUST  closed object schema · §7
    "type": "object",
    "properties": { /* every one described */ },
    "required": ["accountId"],                 //       explicit, even when empty
    "additionalProperties": false              //       always false
  },

  "outputSchema": { /* … */ },                  // MUST  required by this standard · §8

  "annotations": {                             // MUST  all four, explicitly · §9
    "readOnlyHint":    true,                    //       changes nothing, anywhere
    "destructiveHint": false,                   //       may be irreversible
    "idempotentHint":  true,                    //       repeat call has no extra effect
    "openWorldHint":   false                    //       reaches outside the firm
  },

  "icons": [ /* … */ ],                        // MAY   decorative only, never semantic

  "_meta": {                                   // MUST  never enters the model's context · §10
    "com.example.tooling/governance": { /* version, lifecycle, riskTier, owner,
        conformanceLevel, dataClassification, containsPii, piiFields, entitlements,
        approval, recordKeeping, cost, rateLimit, dependencies, availability,
        evaluation, deprecation */ }
  }
}
The ratio test

About half the document is prose addressed to a model and a quarter is metadata addressed to a governance process. If yours inverts that, it is an API endpoint wearing a costume.
