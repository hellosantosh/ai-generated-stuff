Deliberately absent


  
    
    
  • Lot selection. Readable, not writable: the consequences outlive the conversation, so
      a human instructs it. Chapter 16.
    • 
    
  • Money movement. Out of scope for this catalog, and the agent says so rather than
      reaching for the nearest thing.
    • 
    
  • A “sell everything” tool. There is no capability that operates on a whole
      account, which is what makes that instruction unperformable rather than merely refused.
    • 
    
  • Anything that writes a watchlist, a note or a preference. Not because they are
      dangerous, but because a catalog grows by inertia and every tool costs tokens on every
      turn.

    Fifteen codes, closed. Each one's retry semantics, what the agent should do, and where it comes
    from in this catalog.

      fixThe agent's next move

          problem.

Mapping upstream failures


  

    Do not pass a status code through. The same code from two upstreams means different things to an
    agent, and the right next move differs.
  


  

    
UpstreamBecomes
      Because

    
      
404 from the position serviceNOT_FOUND
        The customer does not hold it. The agent should check the positions list.

      
404 from the instrument masterNOT_FOUND
        The ticker does not exist. The agent should search by name.

      
403 on another customer's accountNOT_FOUND
        Never confirm existence. Appendix D's checklist asks about this by name.

      
409 from the order management systemCONFLICT
        Something changed underneath. Re-read before deciding.

      
422 from the risk enginePRECONDITION_FAILED
        Or, better, a blocker inside a successful preview, which is more useful.

      
429 from any upstreamRATE_LIMITED
        And carry the wait, or the agent waits zero seconds.

      
5xx, or a timeoutUPSTREAM_UNAVAILABLE
UPSTREAM_TIMEOUT		
        Distinguish them: one means it certainly did not happen, the other means nobody knows.

Appendix D

  
The review checklist

  

    One page, for the meeting. Everything above the line has already been checked by the build.
  


  

    

      
Before the meeting

      
    
        
  • The linter passes with no errors and no warnings.
    • 
        
  • The contract tests cover each claim the description makes.
    • 
        
  • For tier 2 and above: a trajectory suite and a refusal suite exist and pass.
    • 
        
  • The evaluation scores in the governance block are from a run this week.
    • 
      


      
1. Is the description true?

      
    
        
  • Every sentence holds, read as the model with no other knowledge.
    • 
        
  • “When to use” is in the customer's words, not the firm's.
    • 
        
  • “How to read the result” names fields that still exist.
    • 
        
  • It says which field to read first.
    • 
      


      
2. The nearest tool

      
    
        
  • Name it out loud. Can the reviewer say which utterance hits which?
    • 
        
  • Each description names the other.
    • 
        
  • Both cross-references resolve.
    • 
      


      
3. The confused agent

      
    
        
  • What is the worst thing a well-meaning misreading could do?
    • 
        
  • Would the customer be able to tell it was wrong?
    • 
        
  • For a write tool: does the answer end at the approval gate?
    • 
      

    


    

      
4. The confirmation

      
    
        
  • Render it with real arguments and read it aloud.
    • 
        
  • No (not given) anywhere.
    • 
        
  • It states the priced consequence, not the tool name.
    • 
        
  • It says whether the effect can be undone.
    • 
        
  • It expires.
    • 
      


      
5. Failure

      
    
        
  • Walk each error code the tool can return.
    • 
        
  • Say the agent's next move out loud for each.
    • 
        
  • Nothing leads to “try another tool” that should not.
    • 
        
  • Nothing loops.
    • 
        
  • Another customer's entity gives NOT_FOUND, not
          NOT_ENTITLED.
    • 
      


      
6. Turning it off

      
    
        
  • Trip the kill switch and watch the catalog shrink.
    • 
        
  • Nothing downstream breaks; it just becomes unavailable.
    • 
        
  • The agent stops seeing the tool rather than getting an error.
    • 
      


      
Signatures

      
    
        
  • T0 / T1 — the owning team.
    • 
        
  • T2 — plus one reviewer outside the team.
    • 
        
  • T3 — plus risk or compliance, and a re-certification date.
    • 
      

    

  


  

    If the meeting runs long on anything above, it is a sign. Arguing about
    a name means the ontology is missing a row. Arguing about a risk tier means the policy table is
    missing a rule. Both of those are edits to one file, and both stop the argument happening again.
  







  
Appendix E

  
Glossary

  

    The words this book uses precisely, in the sense it uses them.
  


  

    
Annotation

    
One of four booleans on a descriptor — read-only, destructive, idempotent, open-world
      — that tell the runtime how much to trust a call. Asserted by the author, which is why
      the controls hang on the risk tier instead.


    
Approval reference

    
A hash of the tool name, the canonical arguments and the session. The thing a human's yes is
      recorded against, and the reason an approval cannot be spent on a different order.


    
Blocker

    
A reason an order would be refused, returned inside a successful preview. Distinct
      from a warning, which is something the customer should hear but which would not stop the
      order.


    
Capability

    
One row of the ontology: an operation on an entity, with the identifiers it consumes and
      produces. The tool's name, risk tier and approval mode are derived from it.


    
Cassette

    
A recording of the model's half of one evaluated conversation — which tools it chose,
      with what arguments, in what order. Replayed through the real pipeline, so the suite runs
      offline without becoming a mock.


    
Confirmation token

    
Single-use authority to place one exact order, issued only by the read-only preview and
      bound to a fingerprint of the ticket, a session and an expiry.


    
Conformance level

    
L0 to L3. The answer to “is this tool ready?” in one token, with L3 required for
      anything that changes state.


    
Descriptor

    
The eight-field JSON document that is the tool contract. Four fields the model
      sees, one the caller sees, three only the firm sees.


    
Entity

    
A thing the domain is about, declared in the ontology with its identifier, its
      classification floor and its entitlement floor.


    
Envelope

    
The uniform result shape: ok, data,
      error, meta. Specified once rather than
      repeated in every output schema.


    
Handler

    
The domain code behind one tool. Short, in a well-built catalog, because everything generic
      happens in the pipeline around it.


    
Kill switch

    
A named, hierarchical switch that removes a tool from the published catalog without a
      deployment. Required on every tool at tier 2 or above.


    
Ontology

    
The declaration of what a catalog is about: identifier types, entities, a closed operation
      vocabulary, one capability per tool, and the policies that follow.


    
Pipeline

    
The ten steps between a model emitting a call and a result coming back. Identical for every
      tool, which is why it is in one place.


    
Principal

    
Who a call is for. Established by the runtime from the session, never from an argument.


    
Producer graph

    
Which tool hands out each identifier, and therefore what must happen before what. Derived
      from the capability table, drawn in the console, and written into the system prompt.


    
Registry

    
The one place that knows what tools exist, what they promise, who may call them and what
      code is behind them. Refuses to start on a non-conformant catalog.


    
Risk tier

    
0 to 3, derived from the operation. Drives the approval mode, the evidence required and the
      signatures needed. Not asserted by the tool's author.


    
Selection accuracy

    
Of the evaluated utterances that expected a tool, the share that got it. The headline number,
      and the least interesting of the four on its own.


    
Trace

    
The ordered record of which tools a turn called, with arguments, outcomes and latencies. The
      thing every evaluation assertion is about, and the thing most often missing.
