Glossary

Every term in one place, with the chapter that explains it.

Ambient authority

Credentials such as cookies that the browser attaches automatically, whoever caused the request. (Ch. 2)

Access-Control-Allow-Origin

The response header naming the one origin, or *, allowed to read the response. (Ch. 6)

CORP, COEP, COOP

Cross-Origin Resource, Embedder and Opener Policies: headers controlling embedding and process isolation. (Ch. 19)

CORS

Cross-Origin Resource Sharing: the protocol by which a server lets the browser share its responses with named other origins. (Ch. 6)

CORS-safelisted

The request headers, content types and response headers that need no special permission. (Ch. 7, 10)

Credentials

Cookies, HTTP authentication and TLS client certificates. Sent cross-origin only with credentials: 'include'. (Ch. 9)

Cross-origin isolation

The state of a page served with COOP and COEP, which unlocks features such as SharedArrayBuffer. (Ch. 19)

CSRF

Cross-site request forgery: causing a user's browser to send a state-changing request they didn't intend. Not prevented by CORS. (Ch. 16)

DNS rebinding

Changing what a hostname resolves to, so a browser treats a local address as the same origin as a public site. (Ch. 15, 18)

Fetch Metadata

The Sec-Fetch-* request headers describing how a request came about. (Ch. 19)

Fetch Standard

The WHATWG living standard that defines fetching, including CORS. The authoritative source. (Ch. 6)

JSONP

A pre-CORS technique that delivered data as an executable script. Obsolete. (Ch. 5)

Local Network Access

Chromium's permission-based protection for requests from public sites to local and loopback addresses. (Ch. 18)

Opaque origin

An origin with no identity, serialized as null; never equal to any other origin. (Ch. 3)

Opaque response

The result of a no-cors fetch: usable by the browser, unreadable by script. (Ch. 10)

Origin

The triple of scheme, host and port that the same-origin policy compares. (Ch. 3)

ORB / CORB

Opaque (formerly Cross-Origin) Read Blocking: stops sensitive responses from entering another site's process. (Ch. 19)

Preflight

The OPTIONS request a browser sends to ask permission before a non-simple request. (Ch. 8)

Public Suffix List

The list of suffixes, like .com or .github.io, under which domains are registered; it defines sites. (Ch. 3)

Same-origin policy

The browser rule that a page may read only responses from its own origin, unless CORS permits otherwise. (Ch. 2, 4)

SameSite

A cookie attribute that limits sending the cookie on cross-site requests. (Ch. 9, 16)

Simple request

A request a form could send, which needs no preflight. (Ch. 7)

Site

Scheme plus registrable domain. Coarser than an origin; used by cookies. (Ch. 3)

Vary

The response header listing the request headers a response depends on; Vary: Origin keeps caches correct. (Ch. 17)

XS-Leaks

Cross-site leaks: information inferred from side effects of cross-origin loads. (Ch. 19)
