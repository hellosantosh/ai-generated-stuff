Accounts

Five read-only views of a customer's brokerage accounts: which accounts you can reach, what they are worth, what they hold, what is working, and what has already happened.

Account list

GET/v1/accounts
Requires accounts:read

The entry point for everything else. Returns every account the access token can reach; the accountId here is the opaque, permanent handle used in every other path. 

→ 200 OK
{ "items": [ {
    "accountId":     "acct_01HQ8Z4M2X9K3P7R",
    "accountNumber": "••••4471",
    "nickname":      "Main brokerage",
    "type":          "MARGIN",
    "registration":  "INDIVIDUAL",
    "status":        "ACTIVE",
    "baseCurrency":  "USD",
    "optionsLevel":  "LEVEL_3",
    "dayTrader":     true,
    "_links": {
      "self":         { "href": "…/v1/accounts/acct_01HQ8Z4M2X9K3P7R" },
      "balances":     { "href": "…/balances" },
      "positions":    { "href": "…/positions" },
      "orders":       { "href": "…/orders" },
      "transactions": { "href": "…/transactions" },
      "place-order":  { "href": "…/orders", "method": "POST" }
    }
} ] }
FieldNotes
accountIdOpaque and permanent. Use this as your foreign key.
accountNumberCustomer-facing and masked unless the grant carries accounts:read:full. Display it; never key on it.
typeCASH settles trade-by-trade and cannot borrow; MARGIN can, which changes buying power, short-sale eligibility, and available option strategies.
statusACTIVE · RESTRICTED · CLOSED · PENDING. A restricted account can be read but not traded, and carries no place-order link.
optionsLevelNONE through LEVEL_4. See Options trading.
dayTraderPattern-day-trader flag. When true, the 25,000 USD minimum equity rule applies.
Let the links drive your UI

Rather than encoding "restricted accounts cannot trade" in your client, check whether place-order is present. The server already knows the answer, including rules you have not heard of yet.

Balances

GET/v1/accounts/{accountId}/balances
Requires accounts:read · Cache-Control: no-store during market hours

A snapshot, stamped with asOf. Intraday it reflects live marks and unsettled activity; after the close it settles to end-of-day values. 

→ 200 OK
{ "asOf":                 "2026-08-17T18:42:11Z",
  "currency":             "USD",
  "netLiquidation":       "184320.55",
  "equity":              "184320.55",
  "positionsMarketValue": "142140.45",
  "cash": { "total": "42180.10", "settled": "39900.00",
             "unsettled": "2280.10", "withdrawable": "39900.00" },
  "buyingPower": { "stock": "84360.20", "option": "39900.00",
                    "dayTrading": "168720.40" },
  "margin": { "maintenanceRequirement": "38504.00",
               "excessLiquidity":        "145816.55",
               "marginCall":             null },
  "dayTradesRemaining": 3,
  "patternDayTrader":   true }
Buying power is three different numbers

In a margin account stock is typically twice option — options cannot be bought on margin — and dayTrading is larger still and resets each session. Sizing an option order against buyingPower.stock gets it rejected, and the rejection looks mysterious if you were reading the wrong field.

FieldMeaning
netLiquidationTotal value if everything were liquidated at current marks. The headline number.
cash.settledCash that has completed settlement. In a cash account, spending unsettled proceeds causes a good-faith violation.
cash.withdrawableWhat can actually leave the account today.
margin.excessLiquidityCushion above the maintenance requirement. Approaching zero means a call is imminent.
margin.marginCallNon-null only when a call is outstanding. The one field worth alerting on.
dayTradesRemainingDay trades left in the rolling five-business-day window.

Positions

GET/v1/accounts/{accountId}/positions
Requires positions:read · filters: instrumentType, symbol · paginated

Open positions, one row per instrument and side. Long and short exposure in the same underlying are separate rows. Closed positions do not appear here — use transaction history for realized activity. 

→ 200 OK — a long stock position and a short call written against it
{ "items": [
  { "positionId": "pos_01HQ9A1F4C8M2Q6T",
    "instrument": { "instrumentId": "inst_eq_AAPL", "type": "EQUITY", "symbol": "AAPL" },
    "side": "LONG",
    "quantity":           "500",
    "contractMultiplier": 1,
    "averageCost":        "178.4200",
    "marketValue":        "115575.00",
    "unrealizedPnl":      "26365.00" },

  { "positionId": "pos_01HQ9A3H7D1N4S8V",
    "instrument": {
      "instrumentId": "inst_op_AAPL_20261218C00250000",
      "type": "OPTION", "symbol": "AAPL  261218C00250000",
      "option": { "underlyingSymbol": "AAPL", "expiration": "2026-12-18",
                   "strike": "250.00", "optionType": "CALL",
                   "contractMultiplier": 100 } },
    "side": "SHORT",
    "quantity":           "-5",      // contracts, not shares
    "contractMultiplier": 100,
    "marketValue":        "-4925.00",
    "unrealizedPnl":      "1275.00" }
] }
Options are counted in contracts

A quantity of -5 is five short contracts — exposure to 500 shares. Multiply by contractMultiplier (normally 100; adjusted contracts differ) for share-equivalent exposure. Treating the two as the same unit understates option risk by two orders of magnitude.

quantity is signed, so summing across a portfolio nets long against short correctly.

Order status

GET/v1/accounts/{accountId}/orders
GET/v1/accounts/{accountId}/orders/{orderId}
GET/v1/accounts/{accountId}/orders/{orderId}/executions
Requires orders:read · single-order reads return a strong ETag

With no filter, the collection returns working orders only — PENDING_NEW, NEW, PARTIALLY_FILLED, PENDING_REPLACE, PENDING_CANCEL — which is what a trading screen needs on load. Pass status, or status=ALL, to widen it.

ParameterPurpose
statusRepeatable. One or more statuses, or ALL to disable the working-orders default.
symbolOne underlying, including its option orders.
from, toBounds on createdAt. Defaults to the last 7 days.
cursor, limitPagination. Follow the next link rather than building cursors.
 
GET /v1/accounts/acct_…/orders?status=ALL&symbol=MSFT&limit=25

{ "items": [ {
    "orderId":           "ord_01HQ9D4N7Q1S5U8X",
    "status":            "PARTIALLY_FILLED",
    "side":              "BUY",
    "quantity":          "300",
    "filledQuantity":    "100",
    "remainingQuantity": "200",
    "orderType":         "LIMIT",
    "limitPrice":        "412.50",
    "averageFillPrice":  "412.48",
    "_links": {
      "self":       { "href": "…/orders/ord_01HQ9D4N7Q1S5U8X" },

Executions

One order can fill in many prints across venues. Executions are the audit trail behind filledQuantity and averageFillPrice: 

{ "items": [
  { "executionId": "exec_01HQ9E1A2B3C4D5E", "quantity": "100", "price": "412.48",
    "venue": "XNAS", "liquidity": "REMOVED",
    "executedAt": "2026-08-17T14:33:19.418Z", "settlementDate": "2026-08-19" },
  { "executionId": "exec_01HQ9E4F5G6H7J8K", "quantity": "200", "price": "412.50",
    "venue": "ARCX", "liquidity": "ADDED" }
] }
Poll cheaply, or not at all

Single-order reads are limited to one request per second. Send the previous ETag as If-None-Match and an unchanged order costs a 304 with no body. Better still, use the order event stream and stop polling.

Transaction history

GET/v1/accounts/{accountId}/transactions
Requires transactions:read · filters: from, to, type, symbol

Cash and position activity: trades, dividends, interest, fees, transfers, assignments, exercises, expirations, and corporate actions. Ordered by tradeDate descending. Defaults to the last 90 days; accepts ranges up to 7 years. 

GET /v1/accounts/acct_…/transactions?from=2026-08-01&type=TRADE&type=DIVIDEND

{ "items": [
  { "transactionId":  "txn_01HQ9C2K5M8P1R4W",
    "type":           "TRADE",
    "subType":        "BUY",
    "description":    "Bought 100 AAPL @ 231.05",
    "tradeDate":      "2026-08-15",
    "settlementDate": "2026-08-18",
    "quantity":       "100",
    "price":          "231.0500",
    "grossAmount":    "-23105.00",   // signed: negative reduces cash
    "fees":          [ { "type": "REGULATORY", "amount": "0.00" } ],
    "netAmount":      "-23105.00",   // gross net of fees — the real cash movement
    "relatedOrderId": "ord_01HQ9C1J3L7N0Q3V" }
] }
TypeCovers
TRADEBuys and sells. subType narrows to BUY, SELL, SELL_SHORT, BUY_TO_COVER.
DIVIDEND, INTERESTCash and stock dividends, credit interest.
FEE, TAXCommissions, regulatory fees, margin interest, withholding.
DEPOSIT, WITHDRAWAL, TRANSFER, JOURNALCash and position movement in and out.
ASSIGNMENT, EXERCISE, EXPIRATIONOption lifecycle events. These arrive with no order — nobody placed one.
CORPORATE_ACTIONSplits, mergers, spin-offs, symbol changes.
Reconcile on transactionId

Settlement can back-date an entry, so a transaction may appear in a page you have already read. transactionId is permanent and unique — deduplicate on it rather than summing pages blindly.

A reconciliation keyed on relatedOrderId will silently miss assignments, exercises, and expirations, which have no originating order.
