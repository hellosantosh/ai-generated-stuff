POST/accounts/{accountId}/orders

Place an order

Submit a stock or option order. The request body is a discriminated union on assetClass: EQUITY for single-leg stock and ETF orders, OPTION for single- and multi-leg listed option orders.

Requires orders:write
Parameters
NameInTypeDescription
accountId requiredpathstringOpaque, permanent account identifier from GET /accounts.
Idempotency-Key requiredheaderstringA client-generated UUIDv4 that uniquely identifies this order intent. Reuse it verbatim on every retry. Retained 24 hours.
Request body (required)

application/json

Responses
StatusMeaning
201Order accepted and routed
The order was created. Location points at the new order resource. Check status — an order can be accepted and then immediately rejected by the venue, which surfaces as a later REJECTED state, not as an error on this call.
200Idempotent replay
This exact Idempotency-Key and body were already processed. The original order is returned unchanged and nothing new was created.
400Bad request
The request was syntactically invalid or failed schema validation.
401Unauthorized
The access token is missing, malformed, expired, or revoked. The WWW-Authenticate header names the failure. Refresh and retry once; if the refresh also fails, send the user back through authorization.
403Not permitted
The grant lacks orders:write, or the account is not approved for this trade — most often an options strategy above the account's approval level.
409Conflicting state
The account is restricted, or a conflicting order is already working.
422Unprocessable order
The body parsed and the schema validated, but the order cannot be accepted: insufficient buying power, a price outside collar limits, a closed market for the requested session, an untradable instrument, or an idempotency key reused with a different body.
429Too many requests
Rate limit exceeded. Back off for Retry-After seconds, then retry with full jitter. Repeatedly ignoring Retry-After escalates to a temporary client suspension.
defaultError
An unexpected error, described as RFC 9457 problem details.

PATCH/accounts/{accountId}/orders/{orderId}

Replace (amend) an order

Amend a working order in place. Only quantity, limitPrice, stopPrice, trailingAmount, trailingPercent, netPrice, timeInForce, and goodTilDate may be changed — an amendment that would alter the instrument, side, or leg structure is a different order and must be cancelled and replaced explicitly.

Requires orders:write
Parameters
NameInTypeDescription
accountId requiredpathstringOpaque, permanent account identifier from GET /accounts.
orderId requiredpathstringServer-assigned order identifier.
If-Match requiredheaderstringThe ETag from your most recent read of this order. Required — a mutation without it is rejected with 428 Precondition Required.
Idempotency-Key requiredheaderstringA client-generated UUIDv4 that uniquely identifies this order intent. Reuse it verbatim on every retry. Retained 24 hours.
Request body (required)

application/merge-patch+json

Responses
StatusMeaning

403Forbidden
Authenticated, but not permitted. Either the grant lacks the required scope, or the token is valid for a different account than the one addressed.
