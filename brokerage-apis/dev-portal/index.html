Build on the Brokerage API

Read accounts, positions, and settled activity. Place and manage stock and options orders. Authorize with OAuth 2.1 and PKCE — never with a customer's password.

Quickstart

Five minutes from nothing to a list of accounts. Everything below runs against the sandbox, which is funded with paper money and behaves like production.

1 · Authorize

Send the customer to the authorization server with a PKCE challenge. There is no client secret — PKCE does that work, and a secret shipped in a client binary is not a secret. 

# pkce_auth.py — full source in examples/python/
import base64, hashlib, secrets, urllib.parse

verifier  = base64.urlsafe_b64encode(secrets.token_bytes(32)).decode().rstrip("=")
challenge = base64.urlsafe_b64encode(
    hashlib.sha256(verifier.encode("ascii")).digest()).decode().rstrip("=")

params = {
    "response_type":         "code",
    "client_id":             CLIENT_ID,
    "redirect_uri":          "http://127.0.0.1:8723/callback",
    "scope":                 "accounts:read positions:read orders:read offline_access",
    "state":                 secrets.token_urlsafe(16),
    "code_challenge":        challenge,
    "code_challenge_method": "S256",
}
print("https://auth.brokerage.example.com/oauth2/authorize?"
      + urllib.parse.urlencode(params))
// pkce-auth.mjs — full source in examples/node/
import { createHash, randomBytes } from 'node:crypto';

const codeVerifier  = randomBytes(32).toString('base64url');
const codeChallenge = createHash('sha256').update(codeVerifier).digest('base64url');

const params = new URLSearchParams({
  response_type: 'code',
  client_id: CLIENT_ID,
  redirect_uri: 'http://127.0.0.1:8723/callback',
  scope: 'accounts:read positions:read orders:read offline_access',
  state: randomBytes(16).toString('base64url'),
  code_challenge: codeChallenge,
  code_challenge_method: 'S256',
});

console.log(`https://auth.brokerage.example.com/oauth2/authorize?${params}`);
// PkceAuth.java — full source in examples/java/
byte[] entropy = new byte[32];
new SecureRandom().nextBytes(entropy);
String verifier = Base64.getUrlEncoder().withoutPadding().encodeToString(entropy);

byte[] digest = MessageDigest.getInstance("SHA-256")
        .digest(verifier.getBytes(StandardCharsets.US_ASCII));
String challenge = Base64.getUrlEncoder().withoutPadding().encodeToString(digest);

String url = "https://auth.brokerage.example.com/oauth2/authorize"
        + "?response_type=code&client_id=" + CLIENT_ID
        + "&redirect_uri=" + enc(REDIRECT_URI)
        + "&scope=" + enc("accounts:read positions:read orders:read offline_access")
        + "&state=" + state
        + "&code_challenge=" + challenge
        + "&code_challenge_method=S256";

Read the granted scope

The returned scope may be narrower than what you asked for — the customer can decline individual permissions. Drive your UI from what was granted, not from what you requested.

3 · Call the API

from brokerage_client import BrokerageClient
from decimal import Decimal

client   = BrokerageClient()                # defaults to sandbox
accounts = client.get("/accounts")["items"]
account  = accounts[0]

# Follow the link. Never build the URL by hand.
balances = client.follow(account, "balances")

print(account["accountId"], account["type"])
print(f"Net liquidation: {Decimal(balances['netLiquidation']):,.2f}")
import { BrokerageClient, Dec } from './brokerage-client.mjs';

const client = new BrokerageClient();     // defaults to sandbox
const { items: accounts } = await client.get('/accounts');
const account = accounts[0];

const balances = await client.follow(account, 'balances');

console.log(account.accountId, account.type);
console.log(`Net liquidation: ${Dec.format(balances.netLiquidation)}`);
BrokerageClient client = new BrokerageClient();   // defaults to sandbox
JsonNode account = client.get("/accounts").path("items").get(0);

JsonNode balances = client.follow(account, "balances");

System.out.println(account.path("accountId").asText());
System.out.printf("Net liquidation: %,.2f%n",
        BrokerageClient.decimal(balances, "netLiquidation"));
curl -s https://api.sandbox.brokerage.example.com/v1/accounts \

# Then follow the balances link from the response — do not hand-build it.

Sandbox uses paper money and simulates fills against a delayed book. The surface is functionally identical, so anything you build and test there works in production unchanged.

Make sandbox the default

Configure the base URL so that sandbox is what you get when nothing is set. Reaching production should require a deliberate act, not a missing environment variable. Every example client here is written that way.

Conventions worth knowing before you start

ConventionWhat it means for your code
Hypermedia Every response carries _links. Follow relations rather than constructing URLs, and branch on whether a link is present rather than on a status string — a FILLED order simply has no cancel link.
Money is a string Prices and quantities arrive as decimal strings, so parse them into BigDecimal / Decimal / decimal.js. A float rounding error in a share count is a defect with a dollar value.
Idempotency Order placement requires an Idempotency-Key. Generate one UUID per order intent and reuse it on every retry — a timed-out order may well have been accepted.
ETags Amending or cancelling requires If-Match. It closes the race where an order fills while you are deciding to reprice it.
Errors RFC 9457 problem details. Branch on the type URI; treat title and detail as display text. Log traceId.
Additive changes New fields, enum members, and link relations ship without a version bump. Ignore unknown properties and tolerate unknown enum values.

What this API covers

Stock and listed equity options, for a single authenticated customer's accounts. Three things are deliberately out of scope and have no endpoints here:

Not coveredWhy
Institutional application processAccount opening and suitability review are a compliance workflow on human timescales, not a trading API.
Futures tradingDifferent margin model (SPAN, not Reg T), different contract identifiers, different exchange plumbing.
Crypto tradingDifferent custody model, 24/7 sessions, no settlement cycle, separate regulatory regime.
